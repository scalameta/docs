## What is Metals v2?

Metals v1 has an architecture that makes it hard to support large codebases, especially Bazel monorepos. Metals v2 addresses those gaps and adds new Java support.

### What's Different

Metals v1 requires an expensive sync with the build before IDE features work.

Metals v2 loads symbols from source code instead of only the classpath, so more features work out of the box. Build sync is optional and can happen later.

## Installation

<Steps>
  <Step title="Install the Extension">
    Install **Metals** from the VS Code Marketplace or Open VSX:
    
    - [VS Code Marketplace](https://marketplace.visualstudio.com/items?itemName=scalameta.metals)
    - [Open VSX](https://open-vsx.org/extension/scalameta/metals)
  </Step>
  
  <Step title="Configure Server Version">
    Add to your VS Code `settings.json`:
    
    ```json
    {
      "metals.serverVersion": "2.0.0-M2"" to 
    }
    ```
  </Step>
  
  <Step title="Reload">
    Reload VS Code (`Cmd+Shift+P` → "Reload Window") and open your project.
  </Step>
</Steps>

## Architecture

### Java

Uses **javac** and the **Turbine** header compiler. Indexes multi-million line codebases in seconds with repo-wide navigation.

### Scala

Uses the compiler's `-sourcepath` option to read source files directly, without waiting for the build to produce a classpath. Supports diagnostics and go-to-definition at scale.

---

## 3rd-Party Dependencies

Metals v2 indexes 1st-party sources out of the box. For 3rd-party dependencies, create a `.metals/mbt.json` file:

```json
{
  "dependencyModules": [
    {
      "id": "com.google.guava:guava:33.5.0-jre",
      "jar": "/path/to/guava.jar",
      "sources": "/path/to/guava-sources.jar"
    }
  ]
}
```

Reload the window to navigate to external deps.

### Generated Code

Generated sources (e.g. from Protobuf) require a BSP server. As a workaround, add them as entries in `mbt.json`.

## Known Limitations

Java support has gaps compared to mature Java IDEs.

### Java Code Actions

Limited to import suggestions. Refactorings (extract method, inline variable, move class) are not implemented. Scala has broader support.

### Gradle & Maven

Build import may require manual steps or running a setup script.

### Test & Debug

Requires a BSP server that supports DAP. Setup is more involved than other features.

[Report bugs on GitHub](https://github.com/scalameta/metals/issues).
